# B-100 — Internacionalização

> Wave W10-6 · Trilha D/G · Deps: — · Decisões: D-14

## Problema

Todo texto da UI é PT-BR fixo no template (`lang="pt-BR"` no `index.html`). Não há
catálogo, então qualquer usuário fora do Brasil fica de fora e nenhuma string pode ser
revisada sem mexer em componente.

## Escopo

- `@angular/localize` com catálogo por idioma no repo (D-14).
- `pt-BR` (default) e `en`.
- Extração de todas as strings de UI, incluindo `aria-label`, `title`, `placeholder` e
  mensagens de erro.
- Seleção de idioma: preferência do usuário, com detecção do navegador na primeira vez.
- Data, hora e número formatados pelo locale ativo.
- Plural e gênero via ICU onde faz diferença (“1 mensagem” / “2 mensagens”).
- Build gera um bundle por locale; o service worker respeita o locale ativo.
- Verificação na CI: catálogo sem tradução faltando.

## Fora de escopo

- Terceiro idioma (D-14); RTL; tradução de conteúdo de mensagem; localização das docs
  (`AGENTS.md` mantém docs humanas em PT-BR).

## Contratos

Preferência de idioma no perfil (`Identity`), devolvida no `GET /me` e gravada em
`PUT /me`. É preferência de usuário, não de tenant — a mesma instância atende
pessoas em idiomas diferentes.

Mensagem de erro de API continua em inglês no `error.code`; o cliente traduz pelo
código. Isso evita depender de `Accept-Language` no servidor.

`contratos.md`: campo `locale` no perfil e a regra de tradução por código de erro.

## UX

- Seletor de idioma em Configurações, com o nome no próprio idioma.
- Trocar de idioma recarrega o bundle e mantém a conversa aberta.
- Sem tradução, cai para `pt-BR` — nunca mostra a chave crua.
- Textos em `en` revisados por alguém que fale a língua; tradução automática crua não
  passa em review.

## Multi-tenant e authZ

Nada novo. O locale é preferência pessoal e não influencia autorização nem dado.
Cuidado só com log: mensagem de log continua em inglês, sem interpolar texto traduzido.

## Aceite

- [ ] Toda string visível vem do catálogo (varredura sem literal solto no template)
- [ ] Trocar para `en` traduz a UI inteira, incluindo `aria-label`
- [ ] Datas e números seguem o locale
- [ ] Plural correto em 0, 1 e N
- [ ] Preferência persiste entre sessões e dispositivos
- [ ] Catálogo incompleto **falha** na CI
- [ ] Bundle por locale não infla o carregamento inicial

## Testes

- Unit (web): pipes de data/número por locale; ICU de plural.
- CI: `ng extract-i18n` e comparação com os catálogos; chave faltando reprova.
- E2E: trocar idioma e conferir três telas.

## Riscos

- Strings esquecidas fora do catálogo → verificação na CI, não revisão manual.
- Tradução ruim em `en` → revisão humana obrigatória no PR.
- Bundle por locale multiplicando o build → aceitar dois; o terceiro exige nova decisão.
